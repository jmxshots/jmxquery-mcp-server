Connecting AI agents to Business Central with JMX‑QUERY

The JMX-QUERY MCP Server is a Windows-hosted Model Context Protocol server. It lets AI clients such as GitHub Copilot, Cursor or Claude discover Business Central metadata and run JMX-QUERY scripts, while Business Central decides what each request may read or change. This page explains how the pieces fit together, how to configure them, and what happens when an agent answers a question.

1Architecture at a glance

One server process serves all MCP clients and can connect to any number of Business Central instances. Connection data stays on the server; clients only know the server URL and the MCP key.

MCP clients

Any MCP-capable AI tool. HTTP clients authenticate with the MCP key. Claude Desktop can start a local Stdio process instead.

MCP server

Runs as a Windows service, exposes the MCP tools, validates targets, stores connection data encrypted and writes an audit trail.

Business Central

The JMX-QUERY app parses and executes scripts. Execution contexts define which tables, fields, companies and record counts are allowed.

2JMX-QUERY and what an AI agent can do with it

JMX-QUERY is a compact, pipeline-style query language for Business Central. A script is plain text, runs inside Business Central through the JMX-QUERY app and returns JSON. It reads data with filters, lookups, grouping and aggregates, and it can insert, modify and delete records or run a codeunit, always within the rights of the selected execution context. This makes it a good fit for AI agents: one tool, jmxq_executeScript, covers almost every data task, and Business Central still decides what is allowed.

Language at a glance

Filters

= <> < <= > >=, LIKE with * wildcard (case-insensitive), IN, NOT IN, BETWEEN, combined with AND / OR and parentheses.

Aggregates

COUNT, SUM, AVG, MIN, MAX in SELECT, HAVING and ORDER BY, together with GROUP BY.

Business Central literals

Dates 20250131D, times 0830T, date-times 202501311230DT, GUIDs, and decimals with a dot (1856.40).

Fields and captions

alias."Field" or alias.FIELD(#id). Wildcards alias.* (field names) and alias.$ (captions) project all fields.

Validation

Changes run with validation by default. WITHOUT VALIDATION switches it off; VALIDATE(…) and NOVALIDATE(…) control single fields.

Examples

Aggregate with parameters

PARAMETERS fromDate = 20250101D, toDate = 20251231D
| FROM "G/L Entry" AS gle
| FILTER gle."Posting Date" BETWEEN :fromDate AND :toDate
| GROUP BY gle."G/L Account No."
| SELECT gle."G/L Account No." AS Account,
         SUM(gle.Amount) AS Amount
| HAVING SUM(gle.Amount) <> 0
| ORDER BY Amount DESC
| LIMIT 10

Enrich with a lookup

FROM "Sales Header" AS sh
| LOOKUP Customer AS c
    USING (sh."Sell-to Customer No.") MODE LEFT
| SELECT sh."No." AS DocNo,
         c."No." AS CustNo,
         c.Name AS CustomerName
| LIMIT 50

Preview, then modify

-- 1. preview the affected records
FROM Customer AS c
| FILTER c."Salesperson Code" = 'OLD'
| SELECT COUNT(*) AS Affected

-- 2. change them (after confirmation)
MODIFY Customer AS c
| FILTER c."Salesperson Code" = 'OLD'
| SET ("Salesperson Code" = 'NEW')

Insert with validation control

PARAMETERS no = 'NEW-001', name = 'New Customer'
| INSERT Customer
| RECORD(
    "No." = :no,
    "Name" = VALIDATE(:name),
    "Blocked" = NOVALIDATE(FALSE)
  )

What an AI agent can do

The agent turns a request in natural language into one or more scripts, runs them in the allowed company and explains the result. Typical tasks:

Answer business questions

Reads, filters and ranks data on demand.

“Which ten customers have the highest balance?”

Analyse and compare

Groups and sums, several scripts per question if needed.

“Sales per item category this quarter compared to last quarter.”

Explore the data model

Finds tables and fields, including extension tables.

“Where are vendor prices stored, and what is the primary key?”

Check data quality

Looks for gaps, duplicates and inconsistent values.

“List customers without e-mail address or payment terms.”

Maintain data in bulk

Previews the affected records, asks for confirmation, then changes them within the limits.

“Move all customers of salesperson OLD to NEW.”

Create records

Inserts records from a list or a document, with Business Central validation.

“Create these five contacts from the attached list.”

Run business logic

Calls an allowed codeunit on one record, for example to release a document.

“Release sales order <no.>.”

Write scripts for people

Drafts and explains scripts that users can save and reuse in the JMX-QUERY Script Editor.

“Write a script for the monthly stock check.”

How a well-behaved agent works

Learns the installed version

Loads grammar and examples with jmxq_getGrammar and jmxq_getExamples instead of guessing syntax.

Reads before it writes

Runs the same filter as a read query first and shows what would change.

Asks before changing data

Names instance, company and effect, and waits for confirmation before INSERT, MODIFY, DELETE or RUN CODEUNIT.

Keeps results small

Uses SELECT, LIMIT and aggregates instead of loading whole tables.

Respects the rules

Rejected tables, fields, companies or limits are reported to the user, not worked around.

Context instructions maintained in the execution context reach the agent through jmxq_describeExecutionContext. Use them for scenario-specific rules, such as which tables to prefer or which number series to use.

3Key concepts

Four terms decide where a request goes and what it may do. Two are configured on the MCP server, two in Business Central.

Terminology: tenantId in an OAuth instance is the Entra ID directory ID. It is not a Business Central company. Do not add a company to the instance base URL either; companies are selected separately.

4Setup flow

Setup touches three places: Business Central, the server host and the AI client. Business Central and the server can be prepared in parallel.

Step by step

  1. Install the JMX-QUERY app Business Central Install the JMX-QUERY Business Central app in every instance that the server will connect to. Assign the JMX-QUERY Full Access permission set (plus the business permissions the scenario needs) to the user, service account or Entra application that the MCP server will authenticate as.
  2. Register the web services Business Central Open the JMX-QUERY Script Editor and run Register Web Services. This publishes JMXQ_ApiService and JMXQ_ApiInfoService as OData V4 services, which the MCP server calls.
  3. Define execution contexts Business Central On the page JMX-QUERY Execution Contexts, create one context per use case, for example a read-only sales analysis or a tightly limited data maintenance task:
    • Permissions per table or codeunit: Read, Insert, Modify, Delete, Execute, optionally with allowed fields and security filters.
    • Record limits: Max Read, Insert, Modify and Delete Records.
    • Restrict Companies: the list of companies in which scripts may run.
    • Context Instructions: plain-text guidance that the agent receives when it describes the context.
  4. Install and bootstrap the server Server host On a Windows machine with current Node.js LTS, open an elevated PowerShell in the repository and run npm run bootstrap. It asks for ports, creates or keeps the three keys, builds server and Admin GUI, and optionally installs the Windows service JMX-QUERY MCP Server.
  5. Create an instance in the Admin GUI Server host Open http://<server>:<port>/admin and log in with ADMIN_API_KEY. Choose New instance, enter a stable name and the connection data, then use Test connection and Load companies and pick the technical company.
  6. Verify with the Tool Tester Server host In the Tools view, select the instance, list the execution contexts and run a small read-only script. The Logs view shows the request with duration and status.
  7. Connect the AI client AI client On the Connect page, choose the client and the access location (this computer or local network), copy the generated configuration and provide the JMXQ_MCPAPI_KEY.
  8. Ask the agent AI client Ask a business question. The agent follows the workflow in section 7 and returns the result.

5Configuration reference

Global service settings live in .env. Everything about Business Central (endpoints, credentials, companies) lives in the encrypted Instance Store and is maintained only through the Admin GUI.

Three keys, three purposes

JMXQ_MCPAPI_KEY

Bearer key for MCP clients over HTTP. Give it to client users. Shown on the Connect page.

ADMIN_API_KEY

Login for the Admin GUI and Admin API. Keep it with administrators only.

INSTANCE_MASTER_KEY

Encrypts the Instance Store (min. 32 characters). Back it up; without it the store cannot be read.

6Connecting AI clients

The Connect page in the Admin GUI generates the exact configuration for your server. The examples below show the shape with placeholders. From another computer, never use 127.0.0.1 or localhost: use the server's DNS name or LAN address. 

{
  "inputs": [
    { "id": "jmxq-mcp-api-key", "type": "promptString",
      "description": "JMX-QUERY MCP API key", "password": true }
  ],
  "servers": {
    "jmxq-mcp-server": {
      "type": "http",
      "url": "http://<mcp-host>:<port>/mcp/stream",
      "headers": { "Authorization": "Bearer ${input:jmxq-mcp-api-key}" }
    }
  }
}

VS Code asks for the key once and stores it securely; the key is not written into the file.

{
  "mcpServers": {
    "jmxq-mcp-server": {
      "url": "http://<mcp-host>:<port>/mcp/stream",
      "headers": { "Authorization": "Bearer <JMXQ_MCPAPI_KEY>" }
    }
  }
}
claude mcp add --transport http jmxq-mcp-server http://<mcp-host>:<port>/mcp/stream \
  --header "Authorization: Bearer <JMXQ_MCPAPI_KEY>"

Codex CLI, Gemini CLI and Hermes Agent use the same endpoint; the Connect page generates their config files.

{
  "mcpServers": {
    "jmxq-mcp-server": {
      "command": "C:\\Program Files\\nodejs\\node.exe",
      "args": ["build/index.js"],
      "cwd": "C:\\path\\to\\jmxquery-mcp-server",
      "env": { "JMXQ_STDIO_ONLY": "true" }
    }
  }
}

Starts a separate Stdio-only process on the server computer. It uses no HTTP listener and no MCP key, so it does not conflict with the running service.

7Agent workflow

When a client connects, the server sends workflow instructions. Every Business Central tool call names its target explicitly: the agent does not keep an "active" instance or company between calls, which prevents requests from landing in the wrong system.

Tool overview

ToolPurposeRequired arguments
jmxq_pingConnectivity check, returns pong.none
jmxq_listInstancesFirst call. Returns the enabled instances and whether the user has to choose.none
jmxq_listExecutionContextsContexts visible through the technical company.bcInstance
jmxq_describeExecutionContextPermissions, instructions and allowed execution companies.bcInstance, executionContextCode
jmxq_searchTablesFind tables by wildcard pattern, e.g. *cust*.bcInstance, executionContextCode, searchPattern
jmxq_describeTableFieldsFields and primary key of a table (name or #ID).bcInstance, executionContextCode, tableRef
jmxq_getGrammarJMX-QUERY grammar (EBNF) of the installed app version.bcInstance
jmxq_getExamplesSample scripts published by the installed app.bcInstance
jmxq_getReadmeApiAPI-oriented documentation of the installed app.bcInstance
jmxq_executeScriptRuns a read or write script. Marked as potentially destructive.bcInstance, executionContextCode, executionCompany, script

Example call

{
  "name": "jmxq_executeScript",
  "arguments": {
    "bcInstance": "<instance name>",
    "executionContextCode": "<CONTEXT CODE>",
    "executionCompany": "<allowed company>",
    "script": "<JMX-QUERY script, see below>"
  }
}

A typical read-only script the agent might send (top 10 customers by balance):

FROM Customer AS c
| FILTER c."Balance (LCY)" > 0
| SELECT c."No.", c.Name, c."Balance (LCY)"
| ORDER BY c."Balance (LCY)" DESC
| LIMIT 10

8Security layers

A script reaches data only after passing every layer. The decisive rules sit in Business Central, so they also apply to every other client of the JMX-QUERY app.

Write access: jmxq_executeScript can run INSERT, MODIFY, DELETE and RUN CODEUNIT. Start with read-only execution contexts, grant write rights per table, and keep the record limits small.

Recommendations

Least privilege

One execution context per use case. Prefer explicit table permissions over the "All" switches.

Dedicated BC account

Use a dedicated user or Entra application for each instance, with only the permissions the contexts need.

Separate keys

Use three different random values for MCP key, Admin key and master key. Rotate the MCP key when people leave.

Protect files

Restrict access to .env, data/instances.enc and logs. Logged scripts may contain business data.

Backup and upgrade

  1. Stop the serviceStop JMX-QUERY MCP Server in services.msc.
  2. Back up.env, data/instances.enc and, if audit history matters, the logs folder. Keep the exact INSTANCE_MASTER_KEY.
  3. UpdatePull or extract the new version and run npm run bootstrap (or npm ci and npm run build).
  4. VerifyStart the service, open /admin and call jmxq_listInstances in the Tools view.
